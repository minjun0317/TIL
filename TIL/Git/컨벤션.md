# Git Convention

## 브랜치 컨벤션

```text
feat/#이슈번호-작업내용
fix/#이슈번호-작업내용
refactor/#이슈번호-작업내용
```

### 예시

```text
feat/#12-login-ui
fix/#24-keychain-bug
refactor/#31-auth-manager
```

---

# Convention 종류

## feat

→ 새로운 기능 추가할 때 사용

### 예시

```text
feat/#12-login-ui
feat/#18-chat-screen
feat/#21-signup-api
```

---

## fix

→ 버그 수정할 때 사용

### 예시

```text
fix/#24-keychain-bug
fix/#30-login-error
fix/#41-tabbar-crash
```

---

## refactor

→ 기능 변화 없이 코드 구조만 정리할 때 사용

### 예시

```text
refactor/#31-auth-manager
refactor/#44-network-layer
refactor/#50-folder-structure
```

---

# GitHub Issue란?

→ 해야 할 작업을 정리하는 기능

작업마다 번호가 생성됨

예시:

```text
#12 로그인 UI 구현
#24 Keychain 저장 오류 수정
#31 AuthManager 코드 정리
```

여기서 생성된 번호를 브랜치 이름에 사용하는 것

---

# 작업 순서

## 01 Issue 생성

GitHub Repository → Issues → New issue

### 제목 예시

```text
로그인 UI 구현
채팅 화면 제작
자동 로그인 버그 수정
```

생성하면 번호가 자동 생성됨

```text
#12
#13
#14
```

---

## 02 브랜치 생성

```bash
git switch dev
git pull origin dev
git switch -c "feat/#12-login-ui"
```

---

# 브랜치 이름 구성

```text
feat/#12-login-ui
│
├─ feat           → 작업 종류
├─ #12            → GitHub Issue 번호
└─ login-ui       → 작업 내용
```

---

# 자주 사용하는 Convention

| Convention | 설명 |
|---|---|
| feat | 기능 추가 |
| fix | 버그 수정 |
| refactor | 코드 리팩토링 |
| design | UI 디자인 수정 |
| style | 코드 스타일 수정 |
| docs | 문서 수정 |
| test | 테스트 코드 |
| chore | 설정/패키지 수정 |
