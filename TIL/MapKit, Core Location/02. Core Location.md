# Core Location
➡️ 기기의 **현재 위치, 고도, 방향** 같은 걸 알아내는 프레임워크. 지도는 안 그림. 위치 **데이터**만 줌

## 위치 어떻게 알아내는지
GPS 하나만 쓰는게 아니라 이것저것 섞어서 씀
- **GPS** : 위성 신호. 정확한데 실내에서 잘 안 잡히고 배터리 많이 먹음
- **Wi-Fi** : 주변 와이파이 위치로 추정. 실내에서 강함
- **기지국** : 통신사 기지국 기준. 정확도 낮은데 배터리 적게 먹음

→ 우리가 직접 고르는게 아니라 iOS가 상황 봐서 알아서 섞어줌. 우리는 "이 정도 정확도로 줘" 만 정하면 됨 (밑에 desiredAccuracy)

## 언제 씀
- 지도에 내 위치 띄울 때
- 내 주변 가게, 날씨 보여줄 때
- 러닝앱처럼 이동 경로, 거리, 속도 기록할 때
- 특정 장소 들어가거나 나올 때 알림 (지오펜싱)
- 주소 ↔ 좌표 변환할 때 (`CLGeocoder`)

## MapKit이랑 차이
| | MapKit | Core Location |
|---|---|---|
| 하는 일 | 지도 **보여주기** | 위치 **알아내기** |
| 결과물 | 화면 (UI) | 데이터 (좌표, 속도 등) |
| 권한 | 지도만 띄우는건 권한 필요 없음 | 위치 권한 필요함 |

# CLLocationManager
➡️ Core Location 쓸 때 **창구 역할** 하는 클래스. 권한 요청, 위치 업데이트 시작/중지, 정확도 설정 다 얘한테 시킴

```swift
import CoreLocation

let manager = CLLocationManager()
manager.delegate = self
manager.desiredAccuracy = kCLLocationAccuracyBest
manager.requestWhenInUseAuthorization()   // 권한 요청
manager.startUpdatingLocation()           // 위치 계속 받기 시작
```

- 결과는 바로 return 되는게 아니라 **delegate로 나중에 날아옴**
- ⚠️ 함수 안에서 지역변수로 만들면 함수 끝나자마자 사라져서 delegate 아예 안 불림. 클래스 프로퍼티로 들고 있어야함

.

# CLLocation
➡️ manager가 알려주는 **위치 정보 한 건**. 좌표만 있는게 아니라 그 위치에 대한 정보 묶음임

## 들어있는 정보
| 프로퍼티 | 뜻 |
|---|---|
| `coordinate` | 위도, 경도 (`CLLocationCoordinate2D`) |
| `altitude` | 고도 (m) |
| `horizontalAccuracy` | 좌표 오차 범위 (m). **음수면 값 못 믿음** |
| `verticalAccuracy` | 고도 오차 범위 (m) |
| `speed` | 이동 속도 (m/s). 모르면 -1 |
| `course` | 이동 방향 (0 = 북쪽, 90 = 동쪽) |
| `timestamp` | 이 위치 언제 측정했는지 |
| `floor` | 건물 몇 층인지 (지원되는 건물에서만) |

```swift
let distance = locationA.distance(from: locationB)  // 두 위치 사이 거리 (m)
```
- 거리 계산 함수도 들어있어서 직접 공식 안 짜도 됨

👉 `CLLocationCoordinate2D` 는 **좌표만**, `CLLocation` 은 **좌표 + 언제, 얼마나 정확한지, 속도 등** 다 들어있는 상위호환 느낌

.

# CLLocationManagerDelegate
➡️ CLLocationManager가 결과 알려줄 때 호출하는 함수들 모아놓은 프로토콜

```swift
extension LocationService: CLLocationManagerDelegate {
    // 위치 새로 들어왔을 때
    func locationManager(_ manager: CLLocationManager, didUpdateLocations locations: [CLLocation]) {
        guard let location = locations.last else { return }
        print(location.coordinate)
    }

    // 위치 못 가져왔을 때
    func locationManager(_ manager: CLLocationManager, didFailWithError error: Error) {
        print(error)
    }

    // 권한 상태 바뀌었을 때
    func locationManagerDidChangeAuthorization(_ manager: CLLocationManager) {
        print(manager.authorizationStatus)
    }
}
```

- 위치는 GPS 잡히는 시간 걸려서 언제 올지 모름 → 그래서 delegate로 "오면 알려줘" 하는 구조
- `locations`가 배열인 이유 : 여러개 한꺼번에 몰아서 올 수도 있음. 보통 `.last`가 제일 최신
- 권한 상태 확인을 delegate 처음 연결할 때도 한번 불러줌

# 위치 정보에 왜 권한이 필요함
- 위치는 **집, 회사, 학교, 자주 가는 곳** 다 드러나는 민감한 개인정보임
- 계속 추적하면 그 사람 하루 일과 다 알 수 있음
- 그래서 애플이 앱 맘대로 못 가져가게 막아두고 **사용자가 직접 허락해야만** 줌

## Info.plist 설정 필수
권한 요청할 때 팝업에 "왜 필요한지" 문구 뜨는데 그거 안 적으면 **팝업 자체가 안 뜸**

| 키 | 언제 |
|---|---|
| `NSLocationWhenInUseUsageDescription` | 앱 사용 중 권한 |
| `NSLocationAlwaysAndWhenInUseUsageDescription` | 항상 권한 |

- 문구 대충 "위치가 필요합니다" 이렇게 쓰면 앱스토어 심사에서 리젝 당할 수 있음. "주변 매장을 찾기 위해 위치를 사용합니다" 처럼 **구체적으로** 써야함

# 위치 권한 상태 (CLAuthorizationStatus)

| 상태 | 뜻 |
|---|---|
| `notDetermined` | 아직 한 번도 안 물어봄. 앱 처음 깔았을 때 이 상태 |
| `restricted` | 사용자가 허용하고 싶어도 **못하는** 상태. 자녀 보호 기능(스크린타임)이나 회사 기기 관리 정책으로 막혀있음 |
| `denied` | 사용자가 **직접 거부**함. 아니면 설정에서 위치 서비스 자체를 꺼둔 경우도 이거 |
| `authorizedWhenInUse` | 앱 **사용 중일 때만** 허용 |
| `authorizedAlways` | 앱 안 쓸 때(백그라운드)도 **항상** 허용 |

👉 `restricted`랑 `denied` 둘 다 위치 못 쓰는건 같은데, denied는 사용자가 설정 가서 다시 켤 수 있고 restricted는 사용자도 못 바꿈. 그래서 restricted면 설정 가라고 안내해봤자 의미 없음

## 앱 사용 중 vs 항상

| | 앱 사용 중 (WhenInUse) | 항상 (Always) |
|---|---|---|
| 언제 위치 받음 | 앱 화면 켜져 있을 때 | 앱 꺼져 있어도 |
| 예시 | 지도, 배달앱, 날씨 | 러닝 기록, 가족 위치 공유, 지오펜싱 알림 |
| 요청 방법 | `requestWhenInUseAuthorization()` | `requestAlwaysAuthorization()` |
| 심사 | 무난함 | 왜 필요한지 확실해야 통과됨 |

- Always는 처음부터 바로 못 받음. **WhenInUse 먼저 받고 → 나중에 Always 따로 요청**하는 순서임
- Always 줘도 iOS가 나중에 "이 앱이 백그라운드에서 위치 계속 쓰고 있는데 계속 허용할래?" 하고 사용자한테 다시 물어봄
- 대부분 앱은 WhenInUse로 충분함. Always는 진짜 필요할 때만

+ iOS 14부터 **정확한 위치** 토글도 생김. 사용자가 이거 끄면 권한은 허용인데 위치가 몇 km 단위로 뭉개져서 옴 (`accuracyAuthorization` 이 `.reducedAccuracy`). 날씨앱은 이래도 상관없는데 길찾기는 문제됨

## 💭 생각해보기 - 사용자가 위치 권한 거부하면?
내 생각엔 **거부했다고 앱이 막히면 안 되고, 위치 없이도 쓸 수 있게 만들어야 함**

1. **앱 기능 막지 않기**
   - 위치 거부했다고 빈 화면 띄우거나 앱 못 쓰게 하면 사용자 입장에서 짜증남
   - 기본 위치 (서울시청 같은데)로 지도 띄우거나, 지역 직접 검색해서 쓸 수 있게 대안 줘야함

2. **처음부터 바로 묻지 말기**
   - 앱 켜자마자 권한 팝업 뜨면 뭔지도 모르고 거부 누르기 쉬움 (나도 그럼)
   - "내 주변 보기" 버튼 눌렀을 때처럼 **위치가 왜 필요한지 사용자가 이해한 순간에** 물어보는게 허용률 높음

3. **설정으로 보내주기**
   - iOS는 한번 거부하면 앱에서 팝업 **다시 못 띄움**. `requestWhenInUseAuthorization()` 다시 불러도 아무 반응 없음
   - 그래서 "위치 권한이 꺼져있어요. 설정에서 켜주세요" 안내 + 설정 앱 바로 가는 버튼 주는게 맞다고 생각함

   ```swift
   if let url = URL(string: UIApplication.openSettingsURLString) {
       UIApplication.shared.open(url)
   }
   ```

4. **계속 조르지 않기**
   - 화면 들어갈때마다 알럿 띄우면 오히려 앱 지워버림. 위치 필요한 기능 누를 때만 안내하는게 적당한듯

5. **restricted면 설정 안내 안 하기**
   - 위에 정리한 것처럼 사용자가 못 바꾸는 상태라서 설정 가라고 하면 오히려 혼란줌

# 위치 정확도

## desiredAccuracy
➡️ "위치 이 정도 정확도로 줘" 라고 manager한테 **원하는 정확도** 알려주는 프로퍼티. 단위는 미터

```swift
manager.desiredAccuracy = kCLLocationAccuracyNearestTenMeters
```

| 값 | 정확도 | 이럴 때 |
|---|---|---|
| `kCLLocationAccuracyBestForNavigation` | 최고 (센서까지 다 씀) | 내비게이션 |
| `kCLLocationAccuracyBest` | 아주 높음 (기본값) | 러닝앱 |
| `kCLLocationAccuracyNearestTenMeters` | 약 10m | 주변 가게 찾기 |
| `kCLLocationAccuracyHundredMeters` | 약 100m | 동네 정보 |
| `kCLLocationAccuracyKilometer` | 약 1km | 날씨 |
| `kCLLocationAccuracyThreeKilometers` | 약 3km | 지역 정도만 알면 될 때 |

- "원하는" 정확도라서 무조건 그만큼 정확하게 오는건 아님. 실내면 Best로 해도 오차 큼
- 실제로 얼마나 정확한지는 받은 `CLLocation`의 `horizontalAccuracy` 보고 판단해야함

## 정확도 높이면 무조건 좋음?
➡️ **아님**
- 정확도 높이려면 GPS를 계속 켜놔야함 → **배터리 엄청 빨리 닳음**
- 정확한 위치 잡힐 때까지 **시간도 더 걸림**
- 날씨앱이 10m 단위로 위치 알 필요가 없음. 어차피 동네 단위 날씨 보여줄 거면 Kilometer로 충분함
- 사용자 입장에서도 필요 이상으로 정확한 위치 가져가면 찝찝함

## 정확도 ↔ 배터리
**정확도 ↑ → GPS 많이 씀 → 배터리 ↓**

**정확도 ↓ → Wi-Fi, 기지국 위주 → 배터리 ↑**

반비례 관계라고 보면 됨

## distanceFilter
➡️ **몇 미터 이상 움직여야** 새 위치 알려줄지 정하는 값

```swift
manager.distanceFilter = 50   // 50m 이상 움직였을 때만 didUpdateLocations 호출
```

- 기본값은 `kCLDistanceFilterNone` → 조금만 움직여도 계속 업데이트 옴
- 가만히 서 있어도 GPS 오차 때문에 위치가 미세하게 계속 바뀌어서 delegate 엄청 불림. 그거 거르는 용도
- 업데이트 덜 받으면 그만큼 처리할 일 줄어서 배터리에도 좋음

👉 desiredAccuracy는 **얼마나 정확하게**, distanceFilter는 **얼마나 자주**

## 정확도랑 배터리 같이 고려해야 하는 이유
- 위치 기능은 앱 기능 중에 **배터리 제일 많이 먹는 애들 중 하나**임
- 정확도만 생각하면 배터리 다 닳아서 사용자가 앱 지워버리고, 배터리만 생각하면 위치 엉뚱하게 나와서 기능이 쓸모없어짐
- 그래서 **기능에 딱 필요한 만큼만** 정확도 잡는게 맞음
  - 날씨 → Kilometer, 한 번만
  - 주변 가게 → TenMeters, 한 번만
  - 러닝 기록 → Best + distanceFilter 10m 정도, 계속
  - 내비 → BestForNavigation, 계속
- 위치 다 쓰면 `stopUpdatingLocation()` 꼭 불러서 꺼주는 것도 중요함. 안 끄면 화면 나가도 계속 GPS 돌아감

# 위치 한 번만 받기 vs 계속 받기

| | 한 번만 | 계속 |
|---|---|---|
| 함수 | `requestLocation()` | `startUpdatingLocation()` / `stopUpdatingLocation()` |
| delegate 호출 | 딱 1번 | 위치 바뀔 때마다 계속 |
| 배터리 | 적게 먹음 | 많이 먹음 |
| 예시 | 날씨, 주변 맛집 검색, 게시글에 위치 태그 | 내비, 러닝앱, 배달 기사 위치 |

- `requestLocation()`은 원하는 정확도 맞는 위치 하나 잡히면 알아서 꺼짐
- 계속 받기는 끄는거 까먹으면 안 됨
- "지금 어디야?" 한 번 물어보는거랑 "어디 가는지 계속 실시간으로 알려줘" 차이임

+ iOS 17부터는 delegate 안 쓰고 `CLLocationUpdate.liveUpdates()` 로 async/await 방식으로 받는 방법도 생김. `for try await update in ...` 이런식. 이건 다음 과제 구현할 때 써볼 예정
