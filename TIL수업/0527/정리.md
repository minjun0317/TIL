# Type Casting / Function / Extension

iOS 개발에서 자주 사용하는 Type Casting, Function, Extension에 대해 정리

---

# Type Casting

## 개념

Type Casting은 인스턴스의 실제 타입을 확인하거나 다른 타입처럼 사용하기 위한 문법

Swift 공식문서에서는 인스턴스의 타입을 확인하거나, 클래스 계층 구조 안에서 슈퍼클래스 또는 서브클래스 타입으로 다루기 위한 기능으로 설명

iOS 개발에서는 아래 상황에서 자주 사용

- UIViewController 변환
- UITableViewCell 커스텀 셀 사용
- UICollectionViewCell 커스텀 셀 사용
- Any 타입 값 추출
- Protocol 타입 확인
- Storyboard 화면 전환

---

## 핵심 용어

| 용어 | 설명 | 예시 |
|--------|--------|--------|
| Type Casting | 타입 변환 | vc as? HomeViewController |
| Upcasting | 자식 → 부모 | HomeVC → UIViewController |
| Downcasting | 부모 → 자식 | UIViewController → HomeVC |
| is | 타입 확인 | vc is HomeViewController |
| as | 업캐스팅 | homeVC as UIViewController |
| as? | 안전 캐스팅 | 실패 시 nil |
| as! | 강제 캐스팅 | 실패 시 크래시 |
| Any | 모든 타입 저장 | String, Int, UIView |
| AnyObject | 클래스 타입 저장 | UIViewController |

---

## Upcasting

### 개념

자식 타입을 부모 타입으로 다루는 방식

swift let homeVC = HomeViewController() let vc: UIViewController = homeVC 

Swift에서는 자동으로 처리

---

### 실무 예시

swift let viewControllers: [UIViewController] = [     HomeViewController(),     ProfileViewController(),     SettingViewController() ] 

서로 다른 화면을 하나의 배열로 관리 가능

---

## Downcasting

### 개념

부모 타입을 자식 타입으로 변환하는 방식

swift let vc: UIViewController = HomeViewController() 

현재는 UIViewController 타입으로 인식

swift vc.loadUser() 

오류 발생

---

### 해결

swift if let homeVC = vc as? HomeViewController {     homeVC.loadUser() } 

---

## as?

### 안전한 캐스팅

swift if let cell = tableView.dequeueReusableCell(     withIdentifier: "GanadiCell" ) as? GanadiTableViewCell {      cell.configure() } 

### 특징

- 실패 시 nil 반환
- 앱이 종료되지 않음
- 실무에서 가장 많이 사용

---

## as!

### 강제 캐스팅

swift let cell = tableView.dequeueReusableCell(     withIdentifier: "GanadiCell" ) as! GanadiTableViewCell 

### 특징

- 코드가 짧음
- 실패 시 앱 크래시

---

### 비교

| 구분 | as? | as! |
|--------|--------|--------|
| 실패 | nil | 크래시 |
| 안정성 | 높음 | 낮음 |
| 실무 사용 | 매우 많음 | 제한적 |

---

## is

### 타입 확인

swift if vc is HomeViewController {     print("HomeViewController") } 

타입만 확인하고 변환은 하지 않음

---

### is 와 as?

| 구분 | is | as? |
|--------|--------|--------|
| 역할 | 타입 확인 | 타입 확인 + 변환 |
| 반환 | Bool | Optional |
| 전용 기능 사용 | 불가 | 가능 |

---

## Any

### 모든 타입 저장 가능

swift var value: Any  value = "Ganadi" value = 100 value = UIView() 

---

### 실제 타입 추출

swift if let text = value as? String {     print(text.count) } 

---

## AnyObject

### 클래스 타입만 저장 가능

swift var object: AnyObject  object = UIView() object = UIImageView() object = UIViewController() 

---

### 비교

| 구분 | Any | AnyObject |
|--------|--------|--------|
| 모든 타입 | O | X |
| 클래스 타입 | O | O |
| 값 타입 | O | X |

---

# Function

## 개념

함수는 특정 작업을 하나의 기능으로 묶은 코드

swift func setupUI() {     view.backgroundColor = .white } 

---

## 기본 구조

swift func 함수이름(매개변수: 타입) -> 반환타입 {  } 

---

### 예시

swift func makeGanadiName(name: String) -> String {     return "이름: \(name)" } 

---

## 반환값 없는 함수

swift func setupNavigationBar() {     title = "Ganadi" } 

주로 UI 설정에 사용

---

## 반환값 있는 함수

swift func isValidNickname(_ nickname: String) -> Bool {     return !nickname.isEmpty } 

---

## 함수를 분리하는 이유

| 이유 | 설명 |
|--------|--------|
| 가독성 | 코드가 짧아짐 |
| 유지보수 | 수정 위치 찾기 쉬움 |
| 재사용 | 여러 곳에서 사용 가능 |
| 협업 | 역할 파악 쉬움 |
| 디버깅 | 오류 추적 쉬움 |

---

## 실무 패턴

swift override func viewDidLoad() {     super.viewDidLoad()      setupUI()     setupLayout()     bind()     fetchUser() } 

| 함수 | 역할 |
|--------|--------|
| setupUI() | UI 설정 |
| setupLayout() | 오토레이아웃 |
| bind() | ViewModel 연결 |
| fetchUser() | API 호출 |
| configure() | 데이터 적용 |

# Extension

## 개념

기존 타입에 기능을 추가하는 문법

---

## Extension으로 가능한 것

| 기능 | 설명 |
|--------|--------|
| Computed Property | 계산 프로퍼티 |
| Method | 함수 추가 |
| Initializer | 생성자 추가 |
| Subscript | 인덱스 접근 |
| Nested Type | 내부 타입 |
| Protocol 채택 | 프로토콜 구현 |

---

## ViewController 분리

swift extension HomeViewController {      func setupUI() {      }      func setupLayout() {      } } 

---

### Delegate 분리

swift extension HomeViewController: UITableViewDelegate {  } 

---

### DataSource 분리

swift extension HomeViewController: UITableViewDataSource {  } 

---

## String Extension

swift extension String {      var isNotBlank: Bool {         !trimmingCharacters(             in: .whitespacesAndNewlines         ).isEmpty     } } 

사용

swift if nickname.isNotBlank {  } 

---

## UIColor Extension

swift extension UIColor {      static let ganadiBlue = UIColor(         red: 0.2,         green: 0.4,         blue: 1.0,         alpha: 1.0     ) } 

사용

swift view.backgroundColor = .ganadiBlue 

---

## UIView Extension

swift extension UIView {      func setCornerRadius(         _ radius: CGFloat     ) {         layer.cornerRadius = radius         clipsToBounds = true     } } 

사용

swift profileImageView.setCornerRadius(12)

# Computed Property

## 개념

값을 저장하지 않고 계산해서 반환하는 프로퍼티

---

### Stored Property

swift var nickname = "Ganadi" 

실제 값 저장

---

### Computed Property

swift var nicknameCount: Int {     nickname.count } 

접근할 때마다 계산

---

## 비교

| 구분 | Stored Property | Computed Property |
|--------|--------|--------|
| 값 저장 | O | X |
| 메모리 사용 | O | X |
| 계산 필요 | X | O |

---

## Extension에서 Stored Property 사용 불가

X, 불가능

swift extension String {     var name = "Ganadi" } 

---

O, Computed Property는 가능

swift extension String {      var ganadiText: String {         "Ganadi: \(self)"     } }

# 정리

- Upcasting = 자식 → 부모
- Downcasting = 부모 → 자식
- as? = 안전 캐스팅
- as! = 강제 캐스팅
- is = 타입 확인
- Any = 모든 타입 저장
- AnyObject = 클래스 타입 저장
- Function = 기능 단위로 코드 분리
- Extension = 기존 타입 기능 확장
- Computed Property = 저장하지 않고 계산해서 반환

iOS 개발에서는 Type Casting, Function, Extension, Computed Property가 거의 항상 함께 사용됨

특히 커스텀 셀, 화면 전환, ViewController 분리, String Extension, UIColor Extension, UIView Extension 구현 시 매우 자주 등장
